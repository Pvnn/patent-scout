# Skill: Patent Searcher

## When to Use
Use this skill at **Step 2** of the analysis pipeline. It is triggered after the concept has been successfully abstracted into structured JSON. Its job is to query the local FAISS index (and fallback APIs if needed) to retrieve candidate patents.

## Contract Rules
1. **Pass-through**: The agent must pass the `functional_claims` and `search_keywords` exactly as generated by the Concept Abstractor.
2. **Isolation**: The agent MUST NOT attempt to use its own knowledge to retrieve patents. It must exclusively rely on the `run_tool` subprocess output.

## Output Schema (Structured Output)
The tool subprocess will return a JSON envelope containing the retrieved patents. The agent must pass this array forward.
```json
{
  "ok": true,
  "provider": "FAISS",
  "patents": [
    {
      "patent_number": "US10943XXX",
      "title": "Neural weight clustering method",
      "filing_date": "2023-01-15",
      "assignee": "Tech Corp",
      "independent_claims": ["A method comprising..."]
    }
  ]
}
```

## Tool Call Format
When delegating to the subprocess, invoke the tool exactly as follows:
`run_tool("patent_search", {"functional_claims": ["claim 1"], "search_keywords": ["keyword 1"]})`

## Anti-Patterns
* **Faking patents**: Never hallucinate patent numbers or claims if the tool returns an empty list.
* **Modifying claims**: Do not alter the functional claims before passing them to the tool; the FAISS embeddings rely on the exact phrasing generated in Step 1.
